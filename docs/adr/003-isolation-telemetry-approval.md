# ADR 003 — Source isolation, supplementary telemetry and operator action authority

Status: implemented offline; live cross-account and callback acceptance BLOCKED by account authorization.
Date: 27 October 2026.

The blueprint combines a Review-2 single-account profile with final security-account ownership. Both are now explicit templates: template.yaml retains the original profile; generate_profiles.py produces security.yaml and workload.yaml from it. The security profile owns the trusted gateway, provider and evidence services. The application alone moves to the compromisable workload account. No account-wide policies or organization changes are automated. Resource policies bind the exact external workload role, not every principal in that account. Platform queue cross-account writes remain source-bound to supplementary metadata; no workload role can submit provider observations.

CloudWatch subscription records are corroborative, not execution attestation. Only platform/access-log metadata is selected; application message text is excluded. CloudTrail input pins the S3 object version and records supported AWS APIs; it does not observe arbitrary SaaS HTTPS. The security trail cannot record another account's Lambda actions, so the cross-account profile excludes that unsupported selector. Workload platform logs remain supplementary and compromisable by workload-account administrators. CloudTrail digest files are retained separately; metadata hashes alone do not validate CloudTrail's signing chain.

Provider observations use a dedicated buffered queue after durable provider outbox persistence. The normalizer authenticates queue ARN and assigns source, receipt time and trust tier. Event IDs are namespaced by authenticated source to prevent app/provider collisions. Provider-buffer saturation, stream expiry and retained outbox replay still need live fault testing.

A caller-supplied approved=true is insufficient. A callback broker encrypts the Step Functions task token. An IAM-authenticated operator approves the exact action hash for a bounded interval; the responder verifies the stored proof. Execution names deduplicate repeated findings. Response leases prevent concurrent effects and attempt history is append-only. An arbitrary HTTP 403 cannot prove revocation: verification requires a provider request ID and revoked/integration_disabled reason. Synthetic recovery is a separate approved action, requires the old credential to be revoked and verifies old rejection plus fresh-credential success after reopening. Failure closes the integration. This does not attest that a clean source version has been deployed; code rollback remains a separately reviewed CloudFormation operation.

API deviations: REST APIs provide AWS_IAM source binding; the blueprint's HTTP API label and illustrative route names are adapted to the implemented /evidence endpoint. Opaque JSON client-credentials tokens are intentionally a laboratory contract, not a standards-complete OAuth server. Read-only synthetic records eliminate destructive resource restoration; recovery demonstrates credentials/integration restoration, not arbitrary production data recovery. No novelty or production-readiness claim follows.
