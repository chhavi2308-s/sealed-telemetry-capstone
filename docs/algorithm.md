# IBER algorithm and assumptions

Version iber-1 consumes only canonical evidence, evaluation time and source-health observations. Scenario IDs are opaque metadata, never classifying inputs. Ground truth is loaded only by the evaluator after predictions.

Each provider action opens a case. Candidate expectations must match HMAC credential pseudonym, actor, operation and resource within the configured event-time window plus skew allowance. Conflicting non-null provider request, action or invocation IDs exclude matches. Exact invocation/action bindings reserve an expectation before ambiguous fallback matching. Each expectation describes an intended action; repeated physical requests may still be legitimate retries. Multiple equally plausible expectations, reused fallback bindings and time-only matching remain inconclusive. A denied provider action never becomes successful exfiltration.

States: PENDING while source-specific deadlines remain open; CONSISTENT for independently expected exact matches with app evidence; INCONCLUSIVE for missing telemetry, unknown/stale/unhealthy sources, skew and ambiguous fallback; SUSPICIOUS for unmatched successful provider activity after the gateway deadline; CORROBORATED_SUSPECTED_ABUSE requires independent verified revocation evidence followed by contradictory successful provider activity beyond the clock-skew bound. Copied action/invocation metadata alone remains inconclusive because SDK retries can create the same observation. No state establishes theft or attacker identity. The cloud responder verifies actual mock SaaS rejection before issuing successful response evidence; provider-specific propagation limits still apply.

Default deadlines are provisional local configuration: provider/gateway 15s, app 10s, clock-skew allowance 30s, matching window 60s. They are NOT empirically calibrated or a detection SLA. Deadline evaluation is conservative with skew. A one-minute AWS sweep further increases possible latency. Local demos use virtual time to exercise deadlines without sleeping.

Unmatched expectations also open cases. Late observations append decisions; prior local history is retained. Repeated identical sweeps do not add local revisions. Cloud uses a conditional transaction to advance a mutable current-state pointer and append an immutable numbered revision together. Identical sweeps reuse the current revision; a return to a prior state creates a new revision. Append-only IAM protects cloud decision writes from the workload, not from the security administrator.

Pure reconciliation is O(n² log n) worst-case time including stable candidate sorting and O(n²) candidate memory in a bounded batch. The cloud sweep paginates a transient active-credential index, then queries the evidence CredentialIndex. Above 1000 records for one credential it emits an explicit capacity INCONCLUSIVE finding and continues other credentials. A persisted round-robin cursor bounds each sweep to ten credentials and twenty scan pages. Active entries expire after 15 minutes; delayed ingestion reactivates them. Only operational state uses TTL; forensic records remain retained. The GSI is eventually consistent; subsequent sweeps repair transient omissions. Production-scale partitioned scheduling is pending.

Source health is not equivalent to completeness. Local scenarios inject explicit health states with freshness TTL. A separately permissioned cloud monitor emits authenticated heartbeats for gateway, app, provider and collector availability. It checks Lambda deployment state, queue/DLQ conditions and the oldest unacknowledged provider outbox entry through a sparse index. Normalization updates only the newest per-source heartbeat; stale records older than 130s become unknown. Coverage attestations and empirical calibration remain unfinished. A health record establishes operational availability, not perfect completeness. Unknown health yields uncertainty. Tamper detection must run before inference; local report verification and evaluator enforce this, cloud receipt hashes are checked during normalization. Cloud inference checks canonical snapshot integrity and degrades to INCONCLUSIVE on mismatch. scripts/export_incident.py separately reads exact S3 versions and verifies original/canonical/normalized hashes. Coordinated compromise of security storage and receipt trust remains outside the assumed threat boundary.

Deadline calibration is configurable through the ReconciliationPolicy SAM parameter (JSON Policy fields). Invalid, negative or non-finite values fail closed. Transient activation persists for the larger of 15 minutes or the configured deadline plus skew and sweep margin.
