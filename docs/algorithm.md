# IBER algorithm and assumptions

Version iber-1 consumes only canonical evidence, evaluation time and source-health observations. Scenario IDs are opaque metadata, never classifying inputs. Ground truth is loaded only by the evaluator after predictions.

Each provider action opens a case. Candidate expectations must match HMAC credential pseudonym, actor, operation and resource within the configured event-time window plus skew allowance. Conflicting non-null provider request, action or invocation IDs exclude matches. Exact invocation/action bindings reserve an expectation before ambiguous fallback matching. Every expectation authorizes one action. Multiple equally plausible expectations, reused fallback bindings and time-only matching remain inconclusive. A denied provider action never becomes successful exfiltration.

States: PENDING while source-specific deadlines remain open; CONSISTENT for independently expected exact matches with app evidence; INCONCLUSIVE for missing telemetry, unknown/stale/unhealthy sources, skew and ambiguous fallback; SUSPICIOUS for unmatched successful provider activity after the gateway deadline; CORROBORATED_SUSPECTED_ABUSE when one independently registered one-use authorization has multiple distinct successful provider request IDs with the same invocation/action binding after the deadline. The latter establishes a one-use contract violation, not theft. Benign retries must have distinct expectations or a future provider idempotency contract; do not use this rule for retry-permitted integrations.

Default deadlines are provisional local configuration: provider/gateway 15s, app 10s, clock-skew allowance 30s, matching window 60s. They are NOT empirically calibrated or a detection SLA. Deadline evaluation is conservative with skew. A one-minute AWS sweep further increases possible latency. Local demos use virtual time to exercise deadlines without sleeping.

Unmatched expectations also open cases. Late observations append decisions; prior local history is retained. Repeated identical sweeps do not add local revisions. Cloud uses a conditional transaction to advance a mutable current-state pointer and append an immutable numbered revision together. Identical sweeps reuse the current revision; a return to a prior state creates a new revision. Append-only IAM protects cloud decision writes from the workload, not from the security administrator.

Pure reconciliation is O(n²) time and O(n²) candidate memory in a bounded batch. The cloud sweep paginates a transient active-credential index, then queries the evidence CredentialIndex. It fails visibly above 1000 records for one credential. Active entries expire after 15 minutes; delayed ingestion reactivates them. Only operational state uses TTL; forensic records remain retained. The GSI is eventually consistent; subsequent sweeps repair transient omissions. Production-scale partitioned scheduling is pending.

Source health is not equivalent to completeness. Local scenarios inject explicit health states with freshness TTL. A separately permissioned cloud monitor emits authenticated heartbeats for gateway, app, provider and collector availability. It checks Lambda deployment state, queue/DLQ conditions and the oldest unacknowledged provider outbox entry through a sparse index. Normalization updates only the newest per-source heartbeat; stale records older than 130s become unknown. Coverage attestations and empirical calibration remain unfinished. A health record establishes operational availability, not perfect completeness. Unknown health yields uncertainty. Tamper detection must run before inference; local report verification and evaluator enforce this, cloud receipt hashes are checked during normalization. Read-time cloud archive revalidation remains a hardening requirement.
