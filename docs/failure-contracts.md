# Additional failure contracts — current release

The original component contracts remain applicable, with the following implemented updates. Live enforcement/rehearsal is BLOCKED pending approved AWS access.

| Component | Failure detection | Retry/timeout/idempotency | Recovery/rollback | Data/security implications | Acceptance proof |
|---|---|---|---|---|---|
| Supplementary adapters | Lambda errors, async failure queue, source queue/DLQ lag; native origin/version checks | 90s parser timeout; bounded gzip/records; stable UUIDs; partial publish retries are duplicate-safe | Re-read approved native versions/log batches; no fabricated logical invocation | Metadata only; compromised platform can forge messages; native digest validation separate | test_telemetry |
| Intake rejection/quarantine | 400/413, rejection receipt, error class and private poison metadata | Durable rejection enqueue; conditional metadata archive; poison messages remain failed for DLQ | Repair source/schema or replay original provider outbox; do not overwrite an event under same ID | Raw invalid payload intentionally omitted; body representation hashes cannot reconstruct it | test_aws rejection/quarantine cases |
| Provider independent buffering | Outbox pending age, provider queue/DLQ and forwarding errors | SDK connect 2s/read 5s/three total attempts; stream retries/age bounds; stable event IDs | Digest-reviewed original-body outbox replay after repair; no outbox deletion | No successful synthetic response before outbox commit; success is server acceptance, not proof of network delivery | test_cloud_lab/test_redrive |
| Sweeper/capacity | Error/missing-invocation alarms; explicit capacity finding | 90s, reserved concurrency one; ten credentials/twenty pages per sweep; 1,000-record bound | Resume saved cursor, partition/inspect larger groups and re-evaluate retained evidence | Oversized group becomes INCONCLUSIVE; bounded active lifetime/load remain residual limits | test_cloud_detector |
| Operator callback | Principal/boolean/action checks, expiry, hash mismatch, revised case, uncertain callback | Stable approval/execution IDs; stored decision; execution-history verification on lost ack | Retry same approved plan; new reviewed execution/approval for stale/failed workflow | No public task token; acted metadata retained, callback ciphertext removed after acknowledgement | test_approvals/test_operator_safety |
| Response effects | Provider-specific denial reasons/request IDs; current decision check | Lease 60s vs function 40s; maximum three attempts, workflow wait/backoff; negative started keys before effects | Verify per-token revocation before optional disable; unknown stays unverified; historical reemit never repeats effects | Atomic decision-condition/registry transaction blocks stale approval; prior global disable can mask verification | test_cloud_response/stale-decision transaction test |
| Recovery | Old/fresh probe outcomes and failure type | Scoped fresh issuance; retries can leave unused disposable credentials; failure closes integration | Known-good code via reviewed change set; separate approved integration recovery | No automatic high-impact reversal or arbitrary data restoration; never output fresh bearer | test_recovery/local containment-recovery |
| Reports/cleanup | Hash/version mismatch, truncation, undrained queue/outbox, running workflow | Bounded core export, paginated SDK histories, exact cleanup plan digest | Re-export retained versions; quiesce then drain; workload-first approved teardown | No deletion of retained evidence/keys; interrupted attempt is not success; delayed feeds remain possible | test_export/test_cloud_reporting/test_operator_safety |

No retry policy guarantees delivery after service/retention limits expire. Preserve unknown/partial outcomes and actor/action provenance. Health is operational observation rather than proof of complete historical coverage.
