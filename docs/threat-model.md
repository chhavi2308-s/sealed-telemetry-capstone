# Threat model

Assets: disposable lab credential, synthetic resources, provider outbox, canonical evidence, receipts, findings, response decisions, independent labels. Initial attacker controls the application Lambda and may suppress intent or replay a copied test token externally. App role cannot issue expected actions, write provider audit, modify the archive/index/decisions or assume responder roles. Gateway, provider and security roles are outside initial compromise. Security-account/root compromise is excluded; a single account remains vulnerable to its administrators.

Application intent can be fabricated. Provider metadata IDs can be copied; provider request IDs are generated by the provider. One-use authorization counts, not caller metadata absence alone, support replay reconciliation. If both independent authorization and provider evidence are unavailable, classify uncertainty. Real provider audit, rate limits and revocation semantics differ from this mock.

Local SQLite databases do not enforce IAM or administrator-resistant integrity. Hashes verify bytes against retained receipts; they cannot prove truth, complete coverage, or detect coordinated changes to evidence and its hash. Cloud S3 Object Lock protects retained versions; a privileged writer can create a newer version. Version IDs in the index select the retained original. Retained KMS keys must remain usable to decrypt retained evidence.

The public cloud mock SaaS route accepts only synthetic scoped tokens. An absent run UUID is replaced by a provider-generated research identifier, never a fabricated invocation ID. Cloud reconciliation groups by credential fingerprint across runs; run metadata is not an authorization boundary. Token bytes never enter logs, receipts, reports or experiment inputs. An explicitly enabled lab exposure response can return a disposable token to the authorized harness; no production credential is used.
